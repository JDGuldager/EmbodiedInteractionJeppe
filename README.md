# Project Overview

This project explores how bodily movement qualities can be used as input for an interactive digital environment. Instead of directly mapping positional tracking or gestures to interaction, the system interprets webcam-derived movement through simplified movement descriptors inspired by Laban Movement Analysis (LMA), specifically the Effort dimensions of Weight, Time, and Flow.

The prototype creates an action–perception loop in which the user continuously adapts their movement in response to audiovisual feedback generated by the system. The project investigates how movement qualities such as energetic, flowing, sudden, or still motion can shape the atmosphere and behavior of a virtual environment.

The system was implemented in Unity using webcam frame differencing to estimate movement intensity and abruptness in real time.

# Main Reference

## Laban Movement Analysis

The theoretical inspiration for this project is Laban Movement Analysis (LMA), a framework developed by Rudolf Laban for describing and analyzing human movement. LMA approaches movement not simply as spatial motion, but as expressive bodily behavior containing qualitative dimensions.

This project primarily focuses on the Effort component of LMA:

- Weight (light ↔ strong)
- Time (sustained ↔ sudden)
- Flow (bound ↔ free)

Rather than recognizing gestures or tracking exact body positions, the system attempts to approximate these movement qualities computationally through webcam-based motion descriptors.

The project is also informed by embodied interaction theory and action–perception coupling. The user’s movement affects the virtual environment, and the resulting audiovisual feedback influences how the user continues to move. Interaction therefore emerges through a continuous bodily feedback loop rather than discrete commands or symbolic interfaces.

Importantly, this project does **not** claim to perform full Laban Movement Analysis. Instead, it uses LMA as a conceptual and design framework for exploring embodied interaction through simplified computational movement descriptors.

# Implementation

## Webcam Motion Analysis

The prototype uses webcam frame differencing to estimate movement intensity between consecutive frames.

The following descriptors are calculated:

| Descriptor | Meaning |
|---|---|
| Movement Energy | Amount of bodily movement |
| Suddenness | Abrupt changes in movement |
| Time Effort | Scaled suddenness value |
| Stillness | Low movement over time |

These descriptors are interpreted as simplified LMA-inspired Effort dimensions.

---

# Movement States

The system classifies movement into four states:

| State | Description |
|---|---|
| Still | Minimal movement |
| Flowing | Continuous moderate movement |
| Energetic | Strong continuous movement |
| Sudden | Abrupt high-intensity movement |

Each state affects the environment differently through audiovisual feedback.

# Environmental Feedback

## Visual Feedback

The environment responds dynamically to bodily movement:

- Sphere scaling
- Color transitions
- Particle behavior
- Camera zoom
- Camera pulse during sudden movement
- Light intensity changes

## Audio Feedback

The soundscape changes according to movement qualities:

- Increased movement energy raises pitch and volume
- Sudden movement produces abrupt audio changes
- Stillness creates calmer ambient behavior

This creates a continuous action–perception loop between the body and the virtual environment.

# Code Snippets

## Motion Energy Calculation

```csharp
float targetEnergy = rawMotion * motionSensitivity * 0.75f;

movementEnergy = Mathf.Lerp(
    movementEnergy,
    targetEnergy,
    smoothing
);
```

## Time Effort Calculation

```csharp
suddenness = Mathf.Abs(movementEnergy - previousEnergy);

timeEffort = Mathf.Clamp01(suddenness * 20f);
```

## Movement State Detection

```csharp
bool isStill = movementEnergy < stillnessThreshold && timeEffort < 0.2f;
bool isSudden = timeEffort > 0.5f && movementEnergy > 0.12f;
bool isEnergetic = movementEnergy > energeticThreshold;
```

# Reflection

A major challenge in the project was balancing responsiveness and stability. If the webcam analysis became too sensitive, movement states changed erratically. If smoothing was too strong, the interaction felt delayed and disconnected.

Another important limitation is that webcam frame differencing only provides low-level movement information. The system therefore cannot perform full Laban Movement Analysis or understand movement semantically. Instead, it approximates movement qualities computationally.

Despite these limitations, the prototype demonstrates how embodied movement qualities can function as interaction input and how LMA-inspired concepts can inform the design of interactive systems.
